한글 문자열에서 `len(s)` 와 `for range` 로 센 문자가 달라서 당황한 적이 있습니다. 이유는 간단합니다 — Go의 문자열은 **바이트 슬라이스**입니다.

## 왜 다른가

| 표현 | 세는 것 | "한글" 에서 |
| --- | --- | --- |
| `len(s)` | 바이트 수 | 6 |
| `utf8.RuneCountInString(s)` | 룬(문자) 수 | 2 |
| `len([]rune(s))` | 룬 수 (슬라이스 생성) | 2 |

UTF-8 에서 한글 음절은 보통 3바이트입니다. 그래서 문자열을 "글자 수" 로 자르려면 바이트 인덱스가 아니라 룬 단위로 다뤄야 합니다.

```go title="count.go" hl={9,10} numbers
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	s := "Go 언어"
	fmt.Println(len(s))                     // 9   (바이트)
	fmt.Println(utf8.RuneCountInString(s))  // 5   (룬)
}
```

## 실험 기록

Wasm 경계를 넘을 때는 **문자열이 아니라 인덱스와 길이**를 넘기는 게 정석입니다. 이 실험에서는 문자열 인자를 그대로 넘기도록 `syscall/js` 에 맡겼습니다 — 편하지만, 호출마다 UTF-8 변환 비용이 붙습니다.

```go title="main.go" hl={3,4} numbers
js.Global().Set("__anvilRuneCount", js.FuncOf(func(this js.Value, args []js.Value) any {
	text := args[0].String()
	return fmt.Sprintf(`{"bytes":%d,"runes":%d}`, len(text), utf8.RuneCountInString(text))
}))
```

관찰한 것:

- 반환값을 `map[string]any` 로 주면 변환 과정이 불안정했습니다. **JSON 문자열**로 돌려주고 JS에서 파싱하는 쪽이 안전했습니다.
- `main()` 은 `select {}` 로 살려 둡니다. 함수를 전역에 등록한 뒤 런타임이 끝나면 JS 호출이 실패합니다.
- wasm_exec.js 는 TinyGo 배포본에서 그대로 복사해야 합니다(버전이 다르면 초기화가 깨집니다).

> 바이트를 세는 함수와 룬을 세는 함수를 나란히 두면, `len()` 이 왜 위험한지 몸으로 이해됩니다. 슬라이싱도 `[]rune(s)[:n]` 로 해야 안전합니다.
