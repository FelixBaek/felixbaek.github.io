슬라이스를 쓸 때마다 "이거 복사된 건가?"가 헷갈려서 정리했습니다.

## 배열과 슬라이스

Go의 배열은 **길이가 타입에 포함**됩니다. `[3]int` 와 `[4]int` 는 다른 타입이라 서로 대입할 수 없습니다. 슬라이스는 길이를 런타임 값으로 들고 있는 구조체입니다.

```go title="slice.go" hl={4,5} numbers
arr := [3]int{1, 2, 3}   // 배열: 길이가 타입의 일부
sl := []int{1, 2, 3}     // 슬라이스

fmt.Println(len(sl), cap(sl)) // 3 3
fmt.Println(sl[1:3])          // [2 3]  ← 같은 배열을 가리킨다
```

슬라이스가 들고 있는 세 가지:

| 필드 | 의미 |
| --- | --- |
| 포인터 | 데이터가 있는 배열의 시작 위치 |
| len | 지금 보이는 원소 수 |
| cap | 포인터 위치부터 배열 끝까지 남은 칸 수 |

## 규칙으로 정리

`len == cap` 인 상태에서 append 하면 **용량을 늘린 새 배열**로 옮겨 갑니다. 그 전까지는 원본 배열을 공유합니다.

```go title="main.go" hl={6,7} numbers
base := make([]int, 2, 4) // len=2 cap=4
base[0], base[1] = 1, 2

child := base[:1]         // len=1 cap=4 (같은 배열)
child = append(child, 99) // 아직 여유가 있으니 같은 배열을 수정
fmt.Println(base)         // [1 99]  ← base 도 바뀐다

child = append(child, 1, 2, 3, 4) // 여기서 재할당
child[0] = 7
fmt.Println(base)         // [1 99]  ← 이제 더 이상 안 바뀐다
```

기준은 하나입니다. **`cap` 안에서 append 하면 원본이 바뀌고, 넘어서면 안 바뀐다.**

## 헷갈릴 때 쓰는 확인 코드

```go title="check.go" numbers
fmt.Printf("len=%d cap=%d ptr=%p\n", len(s), cap(s), s)
```

- `cap` 이 여유 있는데도 안 바뀌면 슬라이스가 아니라 **배열을 값으로 넘긴 것**일 수 있습니다.
- 함수 인자로 넘길 때도 같은 규칙입니다. 슬라이스 헤더는 값으로 복사되지만 가리키는 배열은 공유됩니다.

> 재할당이 일어나면 포인터가 바뀝니다. `len`, `cap`, 포인터를 함께 찍는 습관이 제일 빠릅니다.
